# BF014.7 — Canonical Property Catalog Integrated Acceptance

**Status:** IN PROGRESS — BF014.7A NEXT / NOT STARTED; BF014.7B-C NOT STARTED

## Purpose

BF014.7 is the parent real-MariaDB acceptance gate for the Canonical Property Catalog Foundation. It proves schema, repositories, catalog and configuration services, authorization and HTTP, seed baseline, dynamic form projection, and regressions work coherently. It adds no product feature.

## Acceptance boundary

The acceptance verifies the approved schema/integrity guards; representative catalog lifecycle, immutable identity, provenance, deterministic bounded reads; configuration allocation, draft/active/historical lifecycle and concurrency evidence; canonical Measurements, Attributes, options and rules; Geography hierarchy with Egypt and 27 Governorates; Developer → Project → Phase integrity with zero seeded development records; and read/mutation authorization boundaries.

Seed packages 001-007 must execute deterministically, record the ledger/checksum, skip matching reruns, reject checksum mismatch, preserve Admin changes, and isolate a failed later package from earlier committed packages.

The exact baseline remains 6 Categories, 20 Unit Types, 6 Measurement Definitions, 15 Attribute Definitions, 9 Attribute Options, 20 active seeded V1 configurations, Egypt plus 27 Governorates, and zero seeded Developers, Projects, and Phases.

BF014.6 projections regress through `GET /property-profile/core-form` and `GET /unit-types/{id}/property-form` for APARTMENT, VILLA, RESIDENTIAL_LAND, and COMMERCIAL_UNIT. They use active configurations only, preserve rules/options/order/privacy, and retain budgets of at most 4 core-form and 8 property-form queries.

Reads require authentication and `property_catalogs.view`; projection reads are not `SYSTEM_ONLY`. Catalog mutation remains `property_catalogs.manage` plus `SYSTEM_ONLY`. System, Franchise, and Partner Agency read contexts, and independent manage/view semantics, are acceptance requirements.

No Owner, Ownership, Organization Property, Listing, identity, private proposal, or cross-organization data may leak. BF014.7 does not implement Property persistence, values, completeness, media, proposals, Listing, workflows, marketplace, sale closing, or frontend UI.

## Execution slices

- **BF014.7A — Parent Integrated Acceptance Test:** create and run the cross-layer real-MariaDB artifact without duplicating every focused test.
- **BF014.7B — Full BF014 Regression Gate:** run the authoritative BF014.1-BF014.6 focused and integrated regressions, including existing concurrency and authorization evidence.
- **BF014.7C — Acceptance Closure:** record evidence and synchronize status.

A failure that implies schema, seed matrix, permission, configuration lifecycle, privacy, or future Property Profile architecture change stops for review. BF014.7 closes only after parent acceptance, exact baseline, seed, lifecycle/concurrency, HTTP/authorization, projection/query/privacy, and required regressions pass with no unresolved defect.
